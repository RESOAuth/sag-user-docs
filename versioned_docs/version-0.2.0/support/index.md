## Reporting a bug, asking for a change, contributing

SAG is open source, and everything below happens in public on the code
repository rather than here:

- **A bug**, including one in these pages:
  [open an issue](https://github.com/RESOAuth/smart-access-gateway/issues/new/choose).
  Say what you did, what happened, and what you expected. Existing issues are
  searchable, so a look first sometimes answers it faster.
- **A change or a new feature**: an issue again, describing the problem rather
  than the patch. Larger ideas are written up as
  [RFCs](https://github.com/RESOAuth/smart-access-gateway/tree/main/docs/rfcs),
  and reading the open ones shows what is already being considered.
- **Code or documentation**:
  [CONTRIBUTING.md](https://github.com/RESOAuth/smart-access-gateway/blob/main/CONTRIBUTING.md)
  explains the process, what a change needs before it is reviewed, and the
  standard tests are held to. This site has its own repository,
  [sag-user-docs](https://github.com/RESOAuth/sag-user-docs), and every page has an
  "edit this page" link at the bottom.

## Reporting a security vulnerability

**Not in a public issue.** Use the private route in
[SECURITY.md](https://github.com/RESOAuth/smart-access-gateway/blob/main/SECURITY.md),
which is GitHub's private vulnerability reporting on the code repository. That
page says which versions are supported, what to put in a report, and how long
an acknowledgement should take.
